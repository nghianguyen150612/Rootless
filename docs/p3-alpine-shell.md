# P3: rootfs execution (PARTIAL)

`rl run -r DIR -- /bin/sh` selects the kernel chroot backend. It opens the root directory, attempts a user namespace and maps the calling UID/GID to namespace ID 0, then requires a private mount namespace and chroot. If user namespace creation fails it attempts the mount namespace with existing capabilities; failures are reported, not silently redirected to the host. The launcher changes to `/` and calls execve with the original argument vector and environment. It replaces itself, preserving the PID, terminal and process group. The caller's process is not changed. Inherited file descriptors remain open as usual and can refer outside the root; chroot is not a security sandbox. No mounts, `/proc`, `/dev`, network isolation, environment sanitation or PATH search are provided. Relative command names are resolved from `/`.

The kernel resolves PT_INTERP *after* chroot, so a normal Alpine musl interpreter and libraries must exist at their guest paths. The kernel handles ELF static PIE, auxiliary vectors and ordinary child execs. The kernel's regular ELF, architecture, permission and mount checks apply. Direct musl invocation would change executable identity and loader semantics and does not fix unhandled filesystem syscalls; it is not used. Terminal interaction, signals and job control have not been demonstrated. Host policy may deny namespace creation, mapping, mount isolation or chroot, especially on Android. Android/Termux: NOT_RUN.

P2 USER_NOTIF intercepts only absolute openat; relative paths, directory descriptors, stat, access, readlink, exec and other operations remain host-native. Its copied tracee paths can race, notification validity and descriptor injection need careful handling, and unhandled calls escape the virtual root. Kernel PT_INTERP lookup does not invoke the guest's openat. Consequently it cannot launch a dynamic rootfs shell correctly and has not been promoted to a rootfs backend. USER_NOTIF is not a security boundary. No userspace fallback is implemented; a host that rejects the namespace/chroot sequence cannot use this route.

Validation on x86_64 Linux 6.18.57: GCC 14.2 build and all nine P0–P2 CTest cases passed. A temporary root containing the host's dynamically linked `/bin/sh`, loader and libc started through `rl`; `cd /etc` and a shell builtin read of a guest marker produced `cwd=/etc value=guest-data`, and exit 23 was preserved. A missing guest executable returned 127. This is mechanism evidence, not Alpine or ARM64 evidence. Clang is unavailable in this environment. Native Alpine AArch64 execution, interactive terminal behavior, Android and comprehensive filesystem/process tests are NOT_RUN. P3 remains PARTIAL until the specified native ARM64 Alpine smoke test succeeds.
